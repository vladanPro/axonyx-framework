# Axonyx 0.5.0 - Managed Session Security

This release coordinates core, runtime, LSP and CLI packages. It establishes a
managed-session security foundation, not a complete account-management product.

## Included

- Session-bound HMAC-SHA-256 CSRF proofs, same-origin delivery and mutation guards.
- Signed, expiring anonymous proofs before login.
- Automatic hidden proofs in framework-rendered local POST action forms, including
  no-JS submission. Personalized HTML is no-store; static build artifacts contain
  only a placeholder, never a user's proof.
- Explicit `Session.refresh()` in action/API handlers, retaining session identity
  and CSRF proof while respecting an absolute lifetime.
- Atomic live-row refresh in memory, SQLite and Postgres; deleted sessions cannot
  be recreated by a delayed refresh.
- Configurable canonical `[server].public_origin` behind reverse proxies.

## Upgrade

Install `create-axonyx` and `cargo-axonyx` 0.5.0. Update application runtime
dependencies to 0.5.0, regenerate backend code, then check and rebuild the app.
Core/plan enums and `AxSessionCookiePolicy` gained public members, so this is a
minor-version compatibility boundary. Custom session stores must implement atomic
`refresh_live`; its default fails closed. Existing stored sessions need no schema
migration, but now obey the configured absolute lifetime from creation.

Set a cryptographically random `AX_SECRET_SESSION_KEY` of at least 32 bytes.
Use Secure cookies and configure `public_origin` to the external HTTPS origin.
`AX_SECRET_SESSION_ABSOLUTE_TTL_SECONDS` defaults to 30 days; sliding expiry is
configured through `AX_SECRET_SESSION_TTL_SECONDS`.

Native submissions accepting HTML receive redirects even when an ActionForm
contains the legacy hidden patch negotiation field. Browser API clients must
obtain a proof from `GET /__axonyx/csrf` and include `X-Axonyx-CSRF` (or the explicit
form/JSON field). Metadata-free, cookie-free API clients retain their own auth path.

## Boundaries

Legacy signed-cookie authentication and arbitrary raw HTML forms require explicit
integration. Custom Rust servers must wire origin/proof guards. Form-containing
streams are buffered for token injection; proof-bearing uploads currently have
limited progress reporting. Anonymous forms expire after 30 minutes and must then
be reloaded. This release does not include JWT refresh pairs, password reset,
email verification, MFA, distributed throttling or protection against every attack.

The release smoke covers credential login, pre-login rejection, native form
delivery, missing/wrong proofs, refresh, logout and revoked-session rejection.
Memory/SQLite tests cover lifetime caps and revoked-row refresh. Postgres lifecycle
checks run in CI with a disposable database.
