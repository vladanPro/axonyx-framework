# Axonyx 0.6.0 - Compiled Pages and Registration Flow

Coordinated beta release for `axonyx-core`, `axonyx-runtime`, `axonyx-lsp`,
`create-axonyx`, and `cargo-axonyx`. Axonyx UI remains at 0.0.71 and
`axonyx-macros` remains at 0.1.0.

## What changed

- Compiled production HTTP routes render complete Pages documents, including
  imported components, loader data, layouts, and parameterized routes.
- Page loaders receive trusted request/session context. Authorization denial
  returns 401 or 403 without rendering protected content or leaking private
  messages; protected pages are not emitted as static output.
- Native action forms return safe HTML on validation failure and preserve
  route identity and field errors without requiring JavaScript.
- Preview and compiled action/API boundaries validate scalar and required
  record inputs before backend operations. Invalid input receives a safe 422
  response; unsupported record contracts fail during diagnostics.
- Registration primitives include server-only password hashing, request-owned
  identity, conflict mapping for SQLite/PostgreSQL, and production HTTP smoke
  coverage for the account lifecycle.
- Scalar addition now has aligned behavior in compiled backend, Pages preview,
  and WASM. Compiled responses expose `Server-Timing` for diagnostics.

## Upgrade

Upgrade both CLI binaries and the application's runtime together to 0.6.0,
then run `cargo ax upgrade`, `cargo ax check`, and `cargo ax build --clean`.
Rebuild production binaries before deploying. No automatic database migration
is included in this release; application-specific account schemas remain the
application's responsibility.

## Release gate

Publish in dependency order: core, runtime, LSP, create, CLI. Confirm the
published version resolves from crates.io before publishing each dependent
crate. A clean registry-only scaffold must pass check, build, and HTTP smoke
before tagging the release or updating the Docker image.
