# Axonyx 0.5.1 - Generated Backend Validation Fixes

Coordinated patch release for core, runtime, LSP, create-axonyx and cargo-axonyx.

## Fixed

- Canonical action/API input types `Int`, `Float`, `Number` and `Bool` now map to
  Rust scalars instead of unresolved type names.
- Membership guards against global JSON lists now compile and execute. Empty
  lists and non-array values reject the guard rather than panicking.
- `else error "message"` and `else error("message")` preserve messages containing
  commas or escaped quotes. Argument scanning also respects nested calls.
- Membership remains `contains(...)` in the shared plan so preview and compiled
  production execution stay compatible, including membership data bindings.

## Upgrade

Install create-axonyx and cargo-axonyx 0.5.1, update the application's runtime to
0.5.1, regenerate backend code and validate both authoring and Rust output:

```sh
cargo ax check
cargo ax build --clean
cargo check
```

No public AST variants, state protocol changes or database migrations are added.
Axonyx UI remains 0.0.71; macros remain 0.1.0. Existing 0.5.0 security boundaries
still apply. The site workaround syntax remains valid and need not be replaced.

## Verification

Rust 1.82 workspace tests and strict all-feature Clippy, 340 CLI tests and the
compiled production-server HTTP smoke cover positive/negative scalar inputs,
list membership and exact validation messages. Runtime and framework CI passed
the implementation PRs before release preparation.
